# Dive Vision：模型、假设与验证

本页面是学习与演示用的单次、开放式潜水计划模拟器，尚未经过临床验证或潜水设备认证。真实潜水需使用经过验证的工具并由受训人员独立核对。

## 架构与数据

页面与图表使用 HTML/CSS/JavaScript，实际计算在 `planner.py` 中执行。`worker.mjs` 加载固定版本 Pyodide 314.0.7，在浏览器内的 Web Worker 中运行 Python。输入以 JSON 参数传递，不作为 Python 源代码执行。首次使用需要访问 Pyodide CDN；无需 Python 服务端。

草稿保存在当前浏览器的 localStorage。页面没有上传潜水输入的 API。网页上的气量条、坐标轴和数值排版仅是渲染；组织压力、气量、海拔换算、氧暴露、停留计划及 SAC 均由 Python 返回。

## 组织模型

- Bühlmann ZHL-16C，氮与氦分别建模，共 16 组组织。首组氮半时为 4 min，氦为 1.51 min；各组 a/b 参数见 `planner.py`。
- 使用 Schreiner 方程精确推进匀速压力变化；恒深停留是压力斜率为零的特例。
- 混合气 a/b 系数按组织内氮、氦分压加权。GF 上限为 `(P_tissue − GF × a) / (1 − GF + GF / b)`。
- 初始组织氮为 `0.7902 × (水面气压 − 0.0627 bar)`，初始氦为零。假设已经适应当地水面气压。
- 环境绝对压力为 `水面气压 + 深度 × 密度(kg/L) × 0.0980665`，不固定使用 10 m/bar。

## 分段与上升规则

每个手动分段表示从上一深度匀速移动到目标深度，耗时就是这次移动的时长；深度相同时为恒深停留。气体用于整个分段；手动换气先在上一段结束深度进行，并计入独立换气耗时。

最后一段结束后，先判断 GF High 下能否直接返回水面。需要减压时，在 GF Low 下寻找首个受限深度作为锚点，随后按深度线性增加 GF，水面使用 GF High。离站前要求当前组织压力已经允许下一深度，同时以不超过 1 s 的间隔检查整个上升过程。上升和停留均继续更新组织压力。

自动停留使用 3 m 深度网格，末站可选 3 m 或 6 m。起始深度或非网格换气深度也可能形成额外停留点。开始减压后每站至少停留 1 min，以 1 min 递增；在该减压站进行的换气耗时计入停留，并在表格中标记“减压换气”。每次换气或附加停留后重新判断减压义务。

需要减压时，浅于所设末站的换气点不会用于自动减压，页面会显示提示。若手动上升已有减压义务，其路径必须满足 GF Low；过浅的分段会被拒绝，请在更深处结束手动分段，让程序生成完整减压上升。

页面已取消换气耗时与自动安全停留设置，两项默认值均为 0。需要停留时，在可视化中明确增加停留分段。TTS 从最后一个手动分段结束算到水面，包含上升、换气和停留。

## 气体与氧暴露

- 支持空气、高氧、纯氧及含氦混合气。自动减压换气选择已启用、当前深度不超过切换深度、氧分压合适且氧比例更高的气体。
- 气量按理想气体计算。SAC/RMV 统一采用 1 bar 等效 L/min；段用量为 `SAC × 平均环境绝对压力 × 时间`，余压为 `初始压力 − 等效用量 / 气瓶水容积`。
- 预留压力是提示阈值，不是应急共气、气体故障或最小气量方案。余压不足时显示实际计算值及提示，不将负值隐藏为零。
- CNS 使用传统 NOAA 单次暴露表，在 0.6–1.6 ata 内对允许时长插值；低于 0.6 ata 不累计，超过 1.6 ata 时标记无法完整估算。bar 先除以 1.01325 换成 ata。未模拟此前暴露或恢复。
- OTU 累计 `时间 × ((PO₂(ata) − 0.5) / 0.5)^(5/6)`，仅 PO₂ > 0.5 ata 时累计。氧暴露按最多 10 s 的时间片中点近似积分。
- SAC 小工具采用 `气瓶容量 × (起始压力 − 结束压力) / 时间 / 平均环境绝对压力`。

## 验证记录

- 100 组确定性随机氮/氦压力更新及 GF 上限，与独立的 DecoTengu 0.14.0 ZHL-16C 实现对照，差值小于 1e-10 bar。
- 在统一水面气压、0.09985 bar/m、20 m/min 下潜、10 m/min 上升、GF 30/85、无额外换气停留的条件下，5 组空气计划的每站停留和总时长与 DecoTengu 对齐：10 m/20 min、30 m/25 min、35 m/40 min、45 m/30 min、60 m/25 min。这里时间指从下潜开始至开始最终上升的运行时间。
- 35 m/40 min 的 C 版回归：18/15/12/9/6/3 m 分别停留 1/1/4/6/14/26 min，共 52 min。
- 原计划器有 16 项自动测试，覆盖半时、Schreiner 分段一致性、减压路径、换气、气量、GF/混合气校验、末站约束、手动上升、换气产生新减压义务、氧暴露单位、SAC 等。
- 浏览器中已验证真实 Pyodide 计算、输入修改清除旧结果、GF 错误提示、停用气体、图表切换、时间游标，以及 768 px iPad 纵向布局无横向溢出。
- CSV 下载测试因浏览器下载权限未获批准而跳过；导出代码已实现，但本次不声称完成下载端到端验证。

运行测试：

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p 'test_diving*.py' -v
```

这些验证只说明所列测试情形通过，不证明整个模型或某次真实潜水安全。未实现重复潜水、残余负荷、CCR、紧急共气、非理想气体修正、氧暴露恢复或飞行等待时间。

## 四页工具扩展（2026-10-29）

### 可视化与 GF99

可视化只执行指定的下潜、停留、上升；停留深度等于上一段结束深度，不添加自动上升或换气耗时。
GF High 和 GF Low 分别绘出固定 GF 对应的参考上限，不覆盖任何一项输入值。越过 GF High 上限会记录提示，仍完成这条输入剖面的模拟。计划页仍保持越限拒绝与自动减压规则。
同一时间点，对第 i 个腔隔：

`GFi = 100 × (PN2i + PHei − Pamb) / (ai + Pamb / bi − Pamb)`

`GF99 = max(0, max_i(GFi))`。不截断超过 100% 的数值。逐腔隔表保留负值，主导正梯度腔隔以圆点突出。
`SurfGF` 使用水面绝对压力替代 Pamb。它与当前深度 GF99 不同。
时间播放和游标展示的是已由 Python 计算出的快照；可视化中 GF High 和 GF Low 不改变用户输入的剖面或 GF99；二者用于分别计算参考上限。
定义参考 [Shearwater GF99 FAQ](https://shearwater.com/pages/petrel-2-support)。

### 分压法混气

输入均为表压。`Pabs = Pgauge + Patmosphere`；0 bar 表压仍有环境气压余气，不等于真空。
对 O₂、He、N₂ 分别求解 `Pinitial(abs) F_initial + Σ ΔPj F_source,j = Ptarget(abs) F_target`。
在至多三组独立组分方程上枚举非负解，校验每组分残差，不将负的补充气量当成可行步骤。
优先选择气源种类最少的可行组合，按表单顺序输出各步最终表压。

所需等效气量为 `ΔP × 水容积`（L at 1 bar）。目标压力低于当前压力、余气组分过量、
气源组分无法配出目标等情况返回不可行与原因；不自动生成放气方案。
气源默认纯氧、纯氦、21% 空气，可修改三种气源的名称、组成和启用状态。
假设等温理想气体、供气压力和库存充足；未建模高压非理想性、温升、供气瓶均压或操作程序。
理论步骤不能替代合格混气人员、氧兼容设备与冷却后的成分实测。
参考 [DAN: Nitrox Production Methods](https://dan.org/alert-diver/article/nitrox-production-methods/)。

### SCR、语言与主题

SCR 定义为 1 bar 等效 L/min；另返回使用气量、平均环境绝对压力和本气瓶对应的表压消耗率。
中文及英文页面共享每种工具的草稿（包括海拔），四种工具相互独立。
主题默认为 system；可选 light/dark，SVG 和表单使用同一套主题颜色。浏览器直接跟随系统主题变化。
所有工具都有中英文测试阶段免责声明。

## 参数界面与逐段速度修订

- 计划页主要参数：GF High、GF Low、上升速度、下降速度、水体、SCR。
- 可视化主要参数：GF High、GF Low、水体、SCR；每个上升/下潜分段有独立速度（m/min），停留分段输入时长。
- 可视化耗时由 Python 计算 `abs(目标深度 − 起始深度) / 速度`，不依赖计划页全局速度；旧草稿的深度和时长先由 Python 换算速度以保留原剖面。
- 环境与高级设置完整保留水体密度（可自定义）、海拔、水面气压、工作 PPO₂、预留压力，以及自动规划使用的减压 SCR、减压 PPO₂、末站深度。
- 气体名称、O₂、He、容量、初压、切换深度在两页均可编辑；计算后显示 N₂、底部 MOD、减压 MOD。
- 可视化仍只执行手动分段，自动规划设置不会暗中增加上升或停留；界面明确标注适用范围。
- 两页均移除换气耗时与安全停留输入，旧浏览器草稿中的这两项不会提交。内核仅保留显式 API 参数的旧行为供既有回归使用，默认均为 0。

## 组织负荷图的归一化显示

16 个腔隔从快到慢横向排列，横条为组织 N₂ 与 He 分压之和。两种气体仍按各自半时独立计算。
Python 返回分段归一化坐标：当总压不超过环境压力时为 `Ptotal / Pambient`，否则为 `1 + (Ptotal − Pambient) / (M − Pambient)`。
环境压力（坐标 1）对齐到绘图区 30% 处，M 值（坐标 2）对齐到 90% 处，绿色、黄色和红色分别表示低于环境压力、环境压力到 M 值、超过 M 值。坐标 3 对应 GF 200%；更大的负荷在图边用箭头表示，右侧 GF 数值保留真实值。
虚线为经水蒸气修正的当前吸入总惰性气体分压；其百分比是相对环境压力的比值，不是组织饱和度。悬停横条可查看该腔隔的 N₂、He、M 值和 GF。
归一化只影响显示，不参与减压规划或组织压力更新。

## 默认移动速度

默认下潜速度为 18 m/min，上升速度为 10 m/min，采用 [Shearwater Perdix 2 技术模式手册的规划器假设](https://www.shearwater.com/wp-content/uploads/2022/05/Perdix-2_Technical_Manual_RevB.pdf)。这是本工具的规划预设，不是 ZHL-16C 系数或适用于所有情况的统一推荐。
可视化的新示例、切换为下潜/上升的分段使用对应默认速度，移动耗时仍由 Python 按深度差计算。计划页主要参数与 Python 缺省设置保持一致；新示例的初始下潜耗时也由 Python 按 18 m/min 计算。
保存的草稿继续保留用户设定；可视化提供“使用默认速度”，只更新移动分段速度，保留深度、气体和停留时长。
